# 0015. 관리자 편집 화면은 JS 를 전제로 하고, 상태는 서버 컴포넌트 + 서버 액션 + useReducer 로 둔다 (TanStack Query, Zustand 없음)
- 상태: 채택 (2026-10)

## 배경
ADR 0013 은 "세션을 읽는 동적 화면에 useActionState 폼을 두면 JS 없는 제출 뒤 결과가 다시 그려지지 않는다"(Next 16.4 + cacheComponents)며
18/19칸 관리자 화면을 JS 전제로 설계하라고 남겼다. 18칸 작업 편집은 사진을 브라우저에서 줄이고(캔버스) 서명 주소로 올리고(진행률) 끌어서 순서를 바꾼다.
CLAUDE.md 스택은 관리자 데이터에 TanStack Query, UI 상태에 Zustand 를 적어 두었다. 실제로 필요한지 정해야 한다.

## 결정
- **작업 만들기/고치기 화면(`/admin/works/new`, `/admin/works/[id]`)은 JS 를 전제로 한다.** JS 가 꺼져 있으면 `<noscript>` 로 안내한다.
  로그인, 로그아웃, 작업 목록 보기는 지금처럼 JS 없이도 된다
- 저장은 FormData 폼 제출이 아니라 **화면 상태(JSON)를 서버 액션 하나에 보낸다** (`saveWorkAction`). zod 는 형태와 요청 크기만, 칸 규칙은 domain/application (ADR 0009)
  - 성공하면 `updateTag("works")` 로 공개 화면 캐시를 비우고, 새 작업은 그 작업의 편집 주소로 `router.replace`, 고치기는 `router.refresh`
  - 편집 중 세션이 끝나면 redirect 하지 않고 `signedOut` 결과를 돌려준다. 입력을 잃지 않고 새 탭에서 다시 로그인해 저장한다
- **읽기는 서버 컴포넌트**가 요청의 관리자 세션 저장소로 한다 (캐시 없음). **편집 상태는 그 화면 하나의 `useReducer`** (`editor-state.ts`)
- **TanStack Query 와 Zustand 는 쓰지 않는다** (의존성에도 넣지 않는다)
  - TanStack Query: 관리자 읽기는 RSC 가 하고, 쓰기 뒤에는 서버가 다시 그린다. 클라이언트 캐시와 재검증을 한 번 더 두면 같은 데이터의 출처가 둘이 된다.
    관리자 1명, 작업 수십 개라 캐시 이득이 없고 번들만 는다
  - Zustand: 상태가 편집 화면 한 트리(폼 + 사진 목록)에만 있고, 화면 사이에 나눌 상태가 없다. props 와 dispatch 로 충분하다
  - 19칸(문의 목록 필터, 새 문의 자동 갱신)에서 클라이언트 캐시나 폴링이 필요해지면 그때 다시 정한다

## 대안
- **JS 없이도 되는 폼**(FormData + 파일 input 으로 서버 액션 제출): 원본 사진이 서버 액션을 지나 Vercel 본문 4.5MB 에 걸리고, 줄이기와 EXIF 지우기를 못 한다.
  ADR 0013 의 동적 화면 문제로 실패 결과도 JS 없이는 보이지 않는다
- **실패를 redirect + 쿼리로 돌려주기(PRG)**: JS 없이도 결과가 보이지만, 사진 목록과 입력을 주소나 쿠키에 담아야 해서 편집 화면에는 맞지 않다
- **TanStack Query 로 목록/편집 데이터 관리**: 낙관적 업데이트와 재시도를 얻지만 위 이유로 지금은 과하다

## 결과
- JS 가 꺼진 브라우저에서는 작업을 고칠 수 없다. 운영자는 최신 브라우저를 쓰는 1명이라 받아들인다
- 끌어서 놓기를 못 쓰는 키보드/터치 사용자는 앞으로/뒤로 버튼, 대표 지정 버튼을 쓴다. 바뀐 결과는 role=status 로 알린다
- 화면 동작은 컴포넌트 테스트(가짜 액션/업로드)와 e2e(인메모리 저장소, 실제 Chromium 에서 줄이기와 업로드)로 확인한다
- CLAUDE.md, README 스택에서 TanStack Query 와 Zustand 를 뺀다
