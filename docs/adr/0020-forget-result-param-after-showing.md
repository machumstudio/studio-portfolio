# 0020. 관리자 결과 알림 주소(`?notice=` 등)는 보여 준 뒤 JS 로 주소창에서만 지운다
- 상태: 채택 (2026-10)

## 배경
관리자 화면의 결과(문의 상태 바꾸기/지우기 `?notice=`, 작업 지우기 `?deleted=1`, 새 작업 `?created=1`)는
폼 POST → 서버 액션 → redirect 의 주소로 온다 (ADR 0013, 0016). JS 가 없어도 redirect 된 화면이 결과를 보여 주기 위해서다.
대신 그 화면을 새로 고치거나 주소를 복사해 다시 열면 지난 결과("‘완료’로 바꿨습니다")가 또 보인다 (ADR 0016 결과에 남긴 것).
비개발자 운영자는 새로 고친 화면의 알림을 "방금 또 바뀌었다"로 읽을 수 있다.

## 결정
- **결과 알림이 있는 화면에 `ForgetResultParam`(클라이언트 컴포넌트)을 두고, 그린 뒤 `history.replaceState` 로 그 주소 값만 지운다.**
  화면(알림 문구, 상태)은 그대로고 다시 불러오지 않는다. Next 라우터는 `replaceState` 를 자기 주소로 받아들인다
- 같은 화면에서 결과가 이어서 오면(확인 → 완료) 컴포넌트는 남아 다시 그려지기만 하므로, 그릴 때마다 주소를 본다
- **JS 가 없으면 지금처럼 주소에 남는다.** JS 없이 결과가 보이는 것(ADR 0013/0016)이 먼저다
- 알림 문구는 주소 값에서만 만든다 (서버 상태 없음). 개인정보는 주소에 들어가지 않는다 (ADR 0016 그대로)

## 대안
- **한 번만 읽는 쿠키(flash)**: 액션이 쿠키에 결과를 넣고 화면이 읽은 뒤 지운다. 주소가 깨끗하고 JS 도 필요 없지만,
  서버 컴포넌트는 쿠키를 지울 수 없어(proxy 나 다음 요청에서 지워야 함) 두 탭에서 결과가 섞이거나 남는다. 뒤로 가기에서 알림이 사라진다
- **결과를 `useActionState` 로 돌려주기**: JS 없이는 결과가 보이지 않는다 (ADR 0013)
- **그대로 두기**: 새로 고침마다 지난 결과가 다시 보인다

## 결과
- JS 가 있으면 새로 고침, 주소 복사, 북마크에 결과 알림이 따라가지 않는다. 뒤로 가기로 돌아와도 알림 없는 주소다
- JS 가 없으면 주소에 남아 새로 고침하면 다시 보인다 (JS 없이 쓰는 경우는 드물고, 결과 화면이 지금 상태를 보여 주므로 틀린 정보는 아니다)
- 새 결과 주소 값을 만들면 그 화면에 `ForgetResultParam` 을 같이 둔다
