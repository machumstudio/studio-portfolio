# 0022. sm 브레이크포인트를 560 으로 두고, 모바일 2열 묶음이 한 줄로 펴지는 폭으로만 쓴다
- 상태: 채택 (2026-10-25)

## 배경
푸터 링크 묶음(4열)은 시안이 390(2열 × 2줄, 왼쪽부터 쌓음)과 768 이상(4열 한 줄)뿐이다.
391~767 에서는 2열이 왼쪽에 붙은 채 오른쪽이 비어 보였다 (600 에서 링크 칸 526 중 약 190 만 씀).
4열 한 줄이 들어가는 가장 좁은 폭이 필요하다. 링크 칸 안쪽 폭은 화면 폭 - 114 (바깥 여백 16×2, 테두리 2, nav 여백 20×2, 목록 여백 20×2)이고,
글자가 넓은 en 의 4열 글자 합이 350 이다.

## 결정
- `--breakpoint-sm: 560px` (Tailwind 기본 sm 640 을 바꾼다. 코드에서 sm 을 쓰던 곳은 없었다)
  - 560 에서 링크 칸 446 = en 글자 350 + 최소 간격 24 × 3 + 여유 24. ko 는 글자 합이 약 200 이라 넉넉하다
- 뜻은 "모바일 2열 묶음이 한 줄로 펴지는 폭". 지금 쓰는 곳은 푸터 링크 하나다
- 푸터 링크 배치
  - 560 미만: 2열이 링크 칸 폭을 반씩 나눈다 (`w-full` + 같은 비율 2열). 390 에서 둘째 열이 시안(en 149)과 비슷한 자리(163)에 온다
  - 560~767: 4열 한 줄 양 끝 맞춤, 최소 간격 24
  - 768 부터: 지금과 같이 왼쪽부터 간격 50 (lg 100)

## 대안
- 임의 브레이크포인트 `min-[560px]:`: 임의값 금지 규칙(ADR 0001)과 어긋난다
- Tailwind 기본 sm(640) 그대로: 560~639 는 2열로 남는다. en 은 560 부터 들어가므로 이름 있는 값을 실제로 들어가는 폭에 맞췄다
- 콘텐츠 폭 기준(flex-wrap 으로 자리가 모자라면 내려가기): 4열이 3 + 1 처럼 어중간하게 꺾인다
- md(768) 부터를 양 끝 맞춤으로 바꾸기: 요청 범위 밖이고 768 이상 배치(시안 노트북의 왼쪽 정렬)와 어긋난다. 그래서 767 → 768 에서 펼친 4열이 왼쪽 정렬로 바뀐다

## 결과
- 브레이크포인트가 sm / md / lg / xl / 3xl 다섯이 된다. sm 은 위 뜻으로만 쓴다
- 시안 비교 차이율: 390 은 문의 10.10 → 10.11%, 나머지 그대로. 1440/1920 은 바뀌지 않는다
- e2e/responsive.spec.ts 가 ko/en 에서 390/480/559(반씩 2열), 560/600/700/767(한 줄, 양 끝, 가로 넘침·줄 꺾임 없음)을 본다
