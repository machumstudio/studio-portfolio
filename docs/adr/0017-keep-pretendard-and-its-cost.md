# 0017. 한글 글꼴은 Pretendard 를 유지한다 (OS 글꼴 전환은 기각)
- 상태: 채택 (2026-10-25). 같은 날 제안한 "한글은 OS 글꼴로" 안은 PR #38 검토에서 기각했다

## 배경
시안은 영문(Manrope)만 있다. 2026-10-23 에 한글이 OS 마다 다르게 보이지 않도록 Pretendard 가변 다이나믹 서브셋(저자 배포본, 92조각 unicode-range)을 넣었고, 용량과 preload 는 20칸에서 다시 보기로 했다.

20칸 측정(Lighthouse 13.5 모바일: 느린 4G·CPU 4배 감속 시뮬레이션, 운영 빌드, 개발 DB):
- 한국어 홈은 글꼴 18파일 468KB(Pretendard 17조각 약 440KB + Manrope 24KB)를 받는다. 영어 홈은 Manrope 1파일 24KB
- Pretendard 조각은 CSS 가 부르는 가장 높은 우선순위 요청이라, Lighthouse 시뮬레이션이 첫 화면(FCP)을 그 다운로드 뒤로 계산하는 회차가 생긴다. 같은 빌드에서 성능 점수가 회차마다 흔들렸다
  - Pretendard 있음: 홈 80/86/95, 문의 81/89/95, 소개 86/95/99 (FCP 0.9s ↔ 2.6s 를 오간다)
  - Pretendard 없음(OS 글꼴): 홈 90/91/96/96/96, 문의 96/99/99/99/99, 소개 96/99/99/99/99
- preload 로는 풀리지 않는다: 페이지마다 필요한 조각이 달라 미리 받을 파일을 정할 수 없고, 받는 양도 그대로다
- 실제 브라우저는 `font-display: swap` 이라 글자를 OS 글꼴로 먼저 그리고 조각이 오면 바꾼다. 첫 화면이 글꼴을 기다리지는 않지만 첫 방문자는 440KB 를 더 받는다

## 결정
- 한글은 Pretendard 가변 다이나믹 서브셋을 그대로 쓴다. `--font-sans`: Manrope → "Pretendard Variable" → OS 한글 글꼴(Apple SD Gothic Neo, 맑은 고딕, Noto Sans KR/CJK KR, 조각이 오기 전과 못 받았을 때) → system-ui
- 이유: 의뢰인 쪽 사용자는 윈도가 많을 것이고, 윈도에서 맑은 고딕 대신 OS 와 상관없이 같은 모양으로 보이는 것이 더 중요하다. 디자인 쪽도 Pretendard 를 선호한다. 성능 점수는 그다음이다
- 비용을 받아들인다: 한국어 첫 방문 약 440KB, 모바일 Lighthouse 성능이 회차에 따라 90 아래로 내려갈 수 있다 (원인은 글꼴). 두 번째 방문부터는 조각이 브라우저 캐시에 있다
- 깜빡임 없이 줄일 수 있는 것만 한다 (20칸에서 해 본 것과 결과는 docs/performance.md "글꼴")

## 기각한 대안
- OS 글꼴로 전환(20칸에 한 번 넣었다가 되돌림): 점수는 96~99 로 안정되고 440KB 를 아끼지만, 윈도에서는 맑은 고딕으로 보여 OS 마다 모양이 다르다
- 페이지 로드 뒤에 Pretendard CSS 를 넣기: 점수는 안정되지만 새로고침할 때마다 OS 글꼴 → Pretendard 로 바뀌는 깜빡임이 생긴다
- 사이트 글자만 담은 서브셋을 직접 만들기: OFL 예약 글꼴 이름 조항 때문에 이름을 바꿔야 하고, 관리자가 쓰는 작업 제목처럼 미리 모르는 글자는 OS 글꼴로 섞여 나온다
- 굵기별 정적 다이나믹 서브셋: 같은 글자에 굵기 하나가 약 190KB 라 굵기 2~3개를 쓰면 가변과 비슷하다
- `font-display: optional`: 요청 자체는 그대로 높은 우선순위로 나가서 시뮬레이션 결과가 같고, 첫 방문은 OS 글꼴로 남는다

## 결과
- 한글은 윈도/맥/모바일에서 같은 모양이다. 시각 비교 차이율은 OS 글꼴 안을 넣기 전과 같다
- 모바일 성능 목표(90+)는 회차에 따라 못 미칠 수 있다. 수치와 원인은 docs/performance.md 에 그대로 적는다
- 성능을 더 우선하는 의뢰라면 기각한 대안의 "OS 글꼴로 전환"이 import 한 줄과 글꼴 이름 하나로 된다
