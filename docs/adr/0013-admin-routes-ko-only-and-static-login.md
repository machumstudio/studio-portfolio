# 0013. 관리자 화면은 언어 접두사 없는 `/admin`(한국어만)에 따로 두고, 로그인 화면은 완전 정적으로 둔다
- 상태: 채택 (2026-10)

## 배경
17칸에서 관리자 로그인(`/admin/login`)과 대시보드(`/admin`)가 생겼다. 공개 사이트는 `[locale]` 아래에서 ko(접두사 없음)/en(`/en`)을 쓴다 (ADR 0002).
관리자도 `[locale]` 아래 `(admin)` 그룹(ADR 0006 이 예로 든 자리)에 둘지, 언어 처리 없이 따로 둘지 정해야 한다.
또 로그인 폼은 13칸 문의 폼처럼 JS 없이도 동작해야 하는데, 이 프로젝트 설정(Next 16.4, `cacheComponents`)에서 확인해 보니 **동적인 부분이 있는 화면은 JS 없는 제출 뒤 `useActionState` 결과가 HTML 에 다시 그려지지 않는다**.
요청 값(쿠키, `searchParams`)을 읽는 화면은 정적 껍데기 + 나중에 채우는 응답(resume)으로 그려지는데, 서버 액션 뒤 resume 경로가 폼 결과(formState)를 HTML 렌더에 넘기지 않는다. 결과는 RSC 데이터에만 실리고 JS 가 없으면 처음 화면 그대로 보인다.
완전 정적 화면(문의 화면)은 액션 뒤 통째로 다시 그려서 결과가 보인다. 최소 재현(같은 폼을 정적/`cookies()` 를 읽는 동적 화면에 둠)으로 확인했다.

## 결정
- 관리자 화면은 `app/admin/` 에 **자기 루트 레이아웃**(html/body, `lang="ko"`)으로 둔다. URL 은 `/admin`, `/admin/login` 이고 언어 접두사가 없다. `/en/admin` 은 404
  - proxy 는 `/admin` 이하를 next-intl 에 넘기지 않고 관리자 세션 빠른 확인만 한다
  - 문구는 메시지 키(`AdminLogin`, `AdminDashboard`)로 쓰고, 화면은 `ko` 로 고정해 읽는다. en 값도 채워 두지만(메시지 검사: ko/en 키 동일) 쓰지 않는다
- 관리자 루트 레이아웃은 `instant = false`: 대시보드처럼 세션을 읽는 화면을 Suspense 로 쪼개지 않고 서버에서 다 그려 보낸다 (JS 없이도 내용이 보인다)
- 검색 제외: 레이아웃 metadata `robots: noindex, nofollow` + proxy 가 모든 관리자 응답에 `X-Robots-Tag: noindex, nofollow`
- **로그인 화면은 요청 값을 하나도 읽지 않는 완전 정적 화면**으로 둔다 (빌드 결과 `○ /admin/login`)
  - 돌아갈 곳(`?next=`)은 proxy 가 로그인 화면 GET 에서 검사해(`safeAdminReturnPath`, 같은 사이트 `/admin` 경로만) 쿠키 `machum-admin-return-to`(path=/admin/login, httpOnly, 10분)에 넣고, 로그인 액션이 읽어 다시 검사한 뒤 지운다
  - "이미 로그인했으면 대시보드로 보내기"는 하지 않는다. 쿠키를 읽어야 해서 화면이 동적이 된다. proxy 의 빠른 확인으로 보내면 위조/만료 쿠키에서 로그인 ↔ 대시보드 순환이 생긴다

## 대안
- `[locale]/(admin)` 그룹: 관리자도 `/en/admin` 이 생긴다. 운영자는 한국어 사용자 한 명이고, 화면/테스트/돌아갈 주소 검사(언어 접두사 경로)가 두 배가 된다. 나중에 영어 관리자가 필요하면 그때 옮긴다
- 로그인 화면에서 `searchParams` 를 읽어 숨은 칸으로 `next` 전달: 가장 흔한 방식이지만 화면이 동적이 되어 JS 없는 실패 결과가 보이지 않는다
- 실패를 `redirect('/admin/login?error=invalid')` 로 돌려주기(PRG): 동적 화면이 되는 건 같고, 이메일을 다시 채우려면 주소에 개인정보가 들어간다
- 서버 액션에서 Referer 로 `next` 읽기: 쿠키가 필요 없지만 브라우저/확장 프로그램이 Referer 를 지우면 조용히 사라진다

## 결과
- 공개 사이트와 관리자 사이를 오가면 루트 레이아웃이 달라 전체 페이지를 다시 불러온다. 관리자는 따로 쓰는 화면이라 문제 삼지 않는다
- 로그인 화면은 정적이라 CDN 에서 바로 나간다. 대신 돌아갈 곳이 쿠키 하나라, 여러 탭에서 서로 다른 `next` 로 로그인 화면을 열면 마지막에 연 값이 쓰인다
- **18/19칸 주의**: 관리자 화면(세션을 읽는 동적 화면)에 `useActionState` 폼을 두면 JS 없는 제출 뒤 오류 표시가 나오지 않는다. 관리자 편집 화면은 JS 를 전제로 하고(드래그 업로드 등), JS 없는 경우는 성공 후 redirect 로 결과 화면을 보여 주는 방식으로 설계한다. Next 가 고치면 이 제약을 지운다
