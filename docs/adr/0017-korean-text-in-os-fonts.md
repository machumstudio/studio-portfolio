# 0017. 한글은 웹 글꼴(Pretendard)을 받지 않고 OS 글꼴로 그린다
- 상태: 채택 (2026-10-25). 2026-10-23 의 "한글 대체 글꼴 Pretendard"(86471e8) 결정을 바꾼다

## 배경
시안은 영문(Manrope)만 있다. 2026-10-23 에 한글이 OS 마다 다르게 보이지 않도록 Pretendard 가변 다이나믹 서브셋(저자 배포본, 92조각 unicode-range)을 넣었고, 용량과 preload 는 20칸에서 다시 보기로 했다.

20칸 측정(Lighthouse 13.5 모바일: 느린 4G·CPU 4배 감속 시뮬레이션, 운영 빌드, 개발 DB, 회차 중앙값):
- 한국어 홈은 글꼴 18파일 468KB(Pretendard 17조각 + Manrope 24KB)를 받는다. 영어 홈은 Manrope 1파일 24KB
- Pretendard 는 CSS 가 부르는 높은 우선순위 요청이라 Lighthouse 시뮬레이션이 첫 화면(FCP)을 그 다운로드 뒤로 계산하는 회차가 생긴다. 같은 빌드에서 성능 점수가 회차마다 흔들렸다
  - Pretendard 있음: 홈 80/86/95, 문의 81/89/95, 소개 86/95/99 (FCP 0.9s ↔ 2.6s 를 오간다)
  - Pretendard 없음: 홈 90/91/96/96/96, 문의 96/99/99/99/99, 소개 96/99/99/99/99 (FCP 0.9~1.1s)
- preload 로는 풀리지 않는다: 페이지마다 필요한 조각이 달라 미리 받을 파일을 정할 수 없고, 받는 양도 그대로다
- 실제 브라우저는 `font-display: swap` 이라 글자를 OS 글꼴로 먼저 그리고 나중에 바꾼다. 그래도 첫 방문자는 440KB 를 더 받는다 (사진이 많은 사이트라 같은 회선을 사진과 나눠 쓴다)

## 결정
- 한글은 웹 글꼴을 받지 않는다. `--font-sans` 는 Manrope 다음에 OS 한글 글꼴을 둔다: `"Apple SD Gothic Neo"`(맥/iOS), `"Malgun Gothic"`(윈도), `"Noto Sans KR"`, `"Noto Sans CJK KR"`(안드로이드/리눅스), 그 뒤 system-ui
- 영문 글꼴은 Manrope 그대로 (next/font, 라틴 서브셋 24KB, 응답 Link 헤더로 미리 받기)
- `pretendard` 패키지는 공유 카드 이미지(`scripts/og-image.mts`)를 그릴 때만 쓴다 (devDependency). 카드 글자는 그림으로 굳어 있어 받는 쪽 글꼴과 상관없다

## 대안
- 그대로 둠: 모양은 OS 와 상관없이 같지만 모바일 점수가 80~95 로 흔들리고 첫 방문 440KB
- 페이지 로드 뒤에 Pretendard CSS 를 넣기: 점수는 안정되지만 새로고침할 때마다 OS 글꼴 → Pretendard 로 바뀌는 깜빡임이 생긴다 (지금보다 나쁜 경험)
- 굵기별 정적 서브셋: 같은 글자에 굵기 하나가 약 190KB 라 굵기 2~3개를 쓰면 가변과 비슷하다
- 사이트 글자만 담은 서브셋을 직접 만들기: OFL 예약 글꼴 이름 때문에 이름을 바꿔야 하고, 관리자가 쓰는 작업 제목처럼 미리 모르는 글자는 OS 글꼴로 섞여 나온다. 빌드 단계도 하나 는다
- `font-display: optional`: 요청 자체는 그대로 높은 우선순위로 나가서 시뮬레이션 결과가 같다

## 결과
- 한국어 페이지의 글꼴 전송량 468KB → 24KB. 모바일 성능 점수가 회차마다 흔들리지 않는다
- 한글 모양이 OS 마다 다르다. 맥/iOS 의 Apple SD Gothic Neo 는 Pretendard 와 거의 같고, 윈도는 맑은 고딕으로 보인다 (국내 포털과 같은 선택)
- 시각 비교 차이율 변화는 모든 페이지에서 ±0.1%p 이내 (home mobile 7.22 → 7.20%, about mobile 16.28 → 16.29%)
- 되돌리기는 `src/lib/fonts.ts` 의 CSS import 한 줄과 `--font-sans` 의 글꼴 이름 한 개다. 모양을 OS 와 상관없이 맞춰야 하는 의뢰라면 대안의 "직접 서브셋"을 먼저 검토한다
