## 측정 방법
운영 주소:
```bash
pnpm lighthouse --base https://machum-studio.vercel.app   # 공개 페이지를 여는 읽기만 한다
```
로컬 운영 빌드:
```bash
VERCEL_ENV=production pnpm build
VERCEL_ENV=production pnpm start          # http://localhost:3000
pnpm lighthouse                           # 다른 터미널. --runs 5, --base http://..., --json 파일
```
스크립트: `scripts/lighthouse.mjs` (페이지 6개 × 모바일/데스크톱, 회차 중앙값과 회차별 성능, FCP 범위, 성능 외 감점 항목, LCP 요소 출력).
CI 에는 넣지 않았다: GitHub 러너는 CPU 를 나눠 써서 점수가 흔들려 합격선으로 쓰기 어렵고, 운영 빌드 + 12개 화면 × 4회로 CI 가 10분 이상 늘어난다. CI 빌드는 인메모리 저장소라 실제 데이터와도 다르다.

## 글꼴 (Pretendard 유지와 그 비용)
- 한국어 페이지는 Pretendard 가변 다이나믹 서브셋 조각을 받는다: 홈 17조각 444KB, 포트폴리오 13조각 337KB, 소개 12조각 311KB, 문의 11조각 285KB (영어 페이지는 0, Manrope 24KB 만)
- Lighthouse 모바일 시뮬레이션은 이 조각(브라우저 우선순위 가장 높음)을 첫 화면(FCP) 앞에 두는 회차가 있어 FCP 가 0.9s ↔ 4.2s 로 오가고 성능 점수가 흔들린다. 같은 빌드에서 Pretendard 를 뺐을 때는 96~99 로 안정됐다 (ADR 0017)
- 실제 브라우저(Chromium, 느린 4G 근사로 따로 확인)에서는 다르다:
  - LCP 사진은 165ms 에 요청해 약 880ms 에 받는다. Pretendard 조각은 첫 레이아웃 뒤인 약 960ms 부터 요청한다. 글꼴이 LCP 사진보다 먼저 회선을 잡지 않는다
  - `font-display: swap` 이라 글자는 OS 글꼴로 먼저 그려진다. 조각이 다 오기까지(홈 약 4s) 한글 모양이 OS 글꼴 → Pretendard 로 바뀐다 (첫 방문만, 이후는 캐시). CLS 는 0
- 깜빡임 없이 줄일 수 있는지 본 것 (20칸):
  - 쓰지 않는 조각을 받는지: 받은 조각은 모두 화면에 보이는 글자의 조각이다. 줄일 것이 없다
  - 글꼴이 LCP 보다 먼저 회선을 잡는지: 위처럼 실제 브라우저에서는 사진이 먼저다. 시뮬레이션만의 문제라 고칠 것이 없다
  - 글꼴 CSS: `@font-face` 92개가 첫 화면을 막는 CSS(gzip 26.6KB)의 약 13.6KB 다. 따로 떼어도 막는 CSS 이기는 같고, 막지 않게 하면 깜빡임이 생겨 그대로 둔다
  - preload: 페이지마다 필요한 조각이 달라 미리 받을 파일을 정할 수 없다
  - 하지 않은 것: 페이지 로드 뒤 넣기(새로고침마다 깜빡임), 직접 서브셋(OFL 예약 글꼴 이름 조항)
- 결과: 코드로 바꾼 것은 없다

## 20칸에서 고친 것
| 무엇 | 전 | 후 |
|---|---|---|
| 첫 화면 LCP 사진: preload → `loading="eager"` + `fetchPriority="high"` | Next 의 preload `<link>` 가 Low 우선순위로 나감 | High. 페이지마다 LCP 사진 하나만 |
| 홈 콜라주 칸별 `sizes` | 7칸이 같은 41vw → 38px 칸도 384~750px 사진 | 칸 폭 = (화면 폭 - page-x) × 칸 비율 |

확인만 한 것
- 그 밖의 사진(갤러리, 카드, 슬라이더, 라이트박스)은 `loading="lazy"`, `sizes` 는 390/768/1024/1440/1920 에서 렌더 폭과 srcset 선택이 한 단계 안
- Supabase Storage 사진도 최적화를 탄다: `next.config.ts` 의 `remotePatterns` 가 `work-photos` 공개 버킷 경로만 허용. 임시로 올린 사진(418KB JPEG)이 `/_next/image?w=640` 으로 WebP 42KB(WebP 를 받지 않는 브라우저는 JPEG 60KB). 다른 버킷 경로는 400
- 글꼴 preload: Manrope 라틴(24KB)은 next/font 가 응답 `Link` 헤더로 미리 받는다
- 레이아웃 이동: 띠배너(마키)와 슬라이더, 사진 칸 모두 자리를 미리 잡아 CLS 0.000. `e2e/layout-shift.spec.ts` 가 6개 페이지 × 3개 화면에서 0.01 미만인지 본다
